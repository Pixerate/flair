## 🌟 Overview

Flair gives products a library of good-looking, configurable visual effects (hero backgrounds, textures, light, image treatments, transitions, loaders, animated icons and charts) and the tools to make more of them, by hand or with an agent.

- ⚡ **Shader engine**:
  - Shadertoy-style GLSL ES 3.00 fragment shaders, with controls declared in the source (`// @control`), including image inputs.
  - Compile errors come back with line numbers that match the source.
  - Pointer input beyond Shadertoy's `iMouse`: `iPointer` (position while over the canvas, eased hover amount, seconds held or since release) `iClicks[8]` (the latest clicks' positions and times) and `iTrail[32]` (where the pointer has been over the last second, newest first), so effects answer hovers, presses, taps and moves. `ShaderRenderer` and standalone pages feed them; `ShaderFrames` takes scripted `pointer`, `clicks` and `trail` for recordings.
  - Sound: `iAudio` (level, bass, mid, treble), `iSpectrum[16]` (64 log-spaced bins) and `iBeat` (seconds since the last beat). `ShaderRenderer.setAudioSource` listens to an `<audio>`/`<video>`, a microphone or any Web Audio node; `analyseAudioBuffer` analyses a decoded track offline, so recordings follow it frame for frame (see [Sound and scrolling](#sound-and-scrolling)).
  - Scrolling: `iScroll` (the canvas's progress through the viewport, page scroll, velocity, and whether it is scrolling), fed by `ShaderRenderer` and scriptable in `ShaderFrames`; vector effects scrub with the page under `trigger: "scroll"`.
  - Live previews (`ShaderRenderer`, with optional `{ alpha: true }` for transparent overlays) and many animated or hover-activated thumbnails on one context (`ThumbnailPool`).
  - Frames at exact times (`ShaderFrames`, on a page or in a Web Worker, out as `ImageData` or `ImageBitmap`), multi-pass effect stacks and feedback (`ShaderPipeline`, `effectStack`), looping GIFs, and standalone HTML pages.
- ✒️ **Vector motion (`@pixerate/flair/vector`)**: animated SVG described as data. Catalog vector effects declare their controls in the picture (`{{name: type …}}`), text included. A change's `ease` is `linear`, `out`, `in-out`, any CSS cubic-bezier as `[x1, y1, x2, y2]` (overshoot allowed), or a spring `{spring: {mass?, stiffness?, damping?, velocity?}}` (defaults 1, 170, 26, 0; it runs for the change's `ms`, then snaps to its end; `springSettleMs` gives a length that settles). A change can play `repeat` whole times (taking `ms × repeat`), with `alternate` running every other cycle backwards, and `strobe` holds its time on a grid of that many frames a second (12 for animation "on twos"). It covers attribute tweens, draw-on strokes, motion along paths, counters (`animateCount` / `formatCount` for DOM elements too), text written letter by letter (`write`, with `scramble` and `caret`), shape morphs between any paths (`morphPaths`, `morphSequence`) and view zooms. A change can also take a `behavior` (a pulse, a decaying oscillation, a seeded wriggle, a springy overshoot), and `orient` turns an element with the path it follows. Every frame is a pure function of time (`svgFrame`), and `SvgPlayer` plays it (with `scrollTrigger`, `hideWhenPaused`, `reset()`, and `trigger: "hover" | "press" | "click" | "scroll"` to play in answer to the pointer or scrub with the page).
- 🎞️ **Motion primitives (`@pixerate/flair/motion`)**: 25 reusable entrances, exits, emphasis and path motions for any element of a vector picture (see [Motion primitives](#motion-primitives)), described as data and expanded into plain vector motion.
- 🎛️ **Effect editor (`@pixerate/flair/editor`)**:
  - A headless editor for an effect's source, values, keyframes, presets and timeline.
  - Built on [`@pixerate/editor`](https://github.com/Pixerate/editor)'s undo history and command registry, with no UI framework assumed.
  - Opens animations made with `@pixerate/editor`'s vector animation editor (`effect.loadAnimation`, `effectDocumentFromAnimation`): shots over vector artwork become a vector effect, with the scene's colour controls and presets, so new effects can be animated there and finished here.
- 🤖 **Agent-native, bring your own model**:
  - Every editing action is a command, and the commands are exposed as MCP-shaped tools.
  - Ships instructions for the model. The host supplies the model, keys and agent loop.
- 🎬 **Directing and interchange**: multi-shot scenes on one board, each shot arranging catalog effects as layers (on pictures, videos and slots the host fills) with catalog transitions and camera moves (3D tilt and motion blur included) between them; validation, fast headless simulation, a renderer-neutral `ScenePlan`, and recording in the browser. Also blend modes, Oklab colour and grading, retiming, timecode, and export to Lottie, Apple Motion, FCP7 XML and CMX 3600 EDL.

## 🏗️ Architecture

```mermaid
graph TD
  subgraph Effects["Effects (no dependencies)"]
    Catalog["catalog: 459 effects + presets"]
    Shader["shader engine: controls, compile, render, GIF, HTML"]
    Vector["vector motion: SvgMotion, SvgPlayer"]
    Time["time: clocks, easing, keyframes, noise"]
  end
  subgraph Editing["Editing (@pixerate/flair/editor)"]
    Doc["EffectDocument: source, values, tracks, presets"]
    Editor["EffectEditor: state, playhead"]
    Cmds["commands → MCP tools"]
  end
  PE["@pixerate/editor: history, commands"]
  Host["Your app: UI (any framework) + your model"]

  Catalog --> Shader
  Catalog --> Vector
  Doc --> Editor
  Editor --> Cmds
  PE --> Editor
  PE --> Cmds
  Editor -- bindShaderRenderer / bindSvgView --> Shader
  Editor --> Vector
  Host --> Editor
  Host -- tool calls --> Cmds
```

Flair stays free of LLM SDKs and UI frameworks. Your app owns the interface and the model. Flair owns the rendering, the effect model and the tool surface.

### 1. Drop in a catalog effect

```ts
import { ShaderRenderer, SvgPlayer, ThumbnailPool, animateCount } from "@pixerate/flair";
import { getEffect, effectDefaults, renderVectorEffect } from "@pixerate/flair/catalog";

// A shader background (overlay effects have `transparent: true`: render them with { alpha: true })
const aurora = getEffect("aurora")!;
if (aurora.kind === "shader") {
  const preview = new ShaderRenderer(document.querySelector("#hero")!);
  preview.setSource(aurora.source);
  preview.setValues(effectDefaults(aurora, { preset: "Ember", values: { uSpeed: 0.5 } }));
}

// Many shader cards sharing one WebGL context, animating only while hovered
const pool = new ThumbnailPool({ hoverOnly: true });
// An effect that builds up once (a path drawing on) replays it each time its card shows, held built when still
const tube = getEffect("glass-tube")!;
if (tube.kind === "shader") pool.register(card, tube.source, effectDefaults(tube), undefined, { build: tube.build });

// An animated SVG effect, with scroll-triggered playback or hover reset (hideWhenPaused + reset())
const spinner = getEffect("spinner")!;
if (spinner.kind === "vector") {
  new SvgPlayer(document.querySelector("#loading")!, renderVectorEffect(spinner, { accent: "#0ea5e9" }), {
    hold: spinner.hold,
  });
}

// A still sticker (no animation): any vector effect as markup, for a page or the server
import { svgFrameMarkup } from "@pixerate/flair/vector";
const sticker = getEffect("die-cut-sticker")!;
if (sticker.kind === "vector") document.querySelector("#badge")!.innerHTML = svgFrameMarkup(renderVectorEffect(sticker, { label: "NEW!", shape: 4 })) ?? "";
// Any animated sticker gives its settled still the same way: svgFrameMarkup shows the last frame by default.

// Standalone DOM number counter using Flair's clock and easing curves
animateCount({
  element: document.querySelector("#year")!,
  from: 2010,
  to: 2026,
  ms: 900,
  ease: "out",
});
```

With `loop: false` a player plays once and stays on its last frame (like CSS `animation-fill-mode: forwards`); add `hideWhenPaused` to hide it at the end instead.

Text effects (`category: "text"`) can sit inside a heading:

- **`inline: true`** frames just the text, from cap height to baseline. The backdrop is hidden, and outlines, glows, underlines and drips spill over the text around it. Inline text keeps its full size at any length: the picture gets wider instead of the text shrinking. Give the container `display: inline-block`, `height: 0.72em` and the viewBox's aspect ratio.
- **Overhang**: each text effect writes `data-overhang="top right bottom left"` (in ems) on its `<svg>`, saying how far it reaches past its box when it comes to rest. `svgInlineLayout(motion.svg)` (from `@pixerate/flair/vector`) reads the aspect ratio and the overhang. Use the overhang as a margin to keep room for drips and glows.
- **Typeface**: every text effect takes `font` and `weight`, and `font: "inherit"` uses the heading's font.
- **Colour**: colour controls take any CSS hex, `rgb()` or `hsl()` colour, or `currentColor` to follow the text colour around it, so one effect suits light and dark themes. Effects whose default text is light on a dark backdrop need an ink colour that shows on your page.

```ts
const motion = renderVectorEffect(getEffect("drip-text") as VectorEffect, { word: "Slop", inline: true, font: "inherit", outline: "currentColor" });
const { aspectRatio, overhang: o } = svgInlineLayout(motion.svg)!;
Object.assign(host.style, { display: "inline-block", height: "0.72em", aspectRatio: `${aspectRatio}`, margin: `${o.top}em ${o.right}em ${o.bottom}em ${o.left}em` });
new SvgPlayer(host, motion, { loop: false });
```

Find effects with `findEffects({ text: "glow", category: "light", kind: "shader" })`, or by a group of related categories with `findEffects({ group: "Backgrounds" })` (`EFFECT_CATEGORY_GROUPS` lists them, and `categoryGroup(category)` gives a category's group). Each effect has an `id`, `name`, `description`, `category`, `tags` and optional `presets`. Tags cut across categories: `findEffects({ tags: ["glass"] })` gathers every glass look (text, panes, lenses, stained glass, a prism) and `tags: ["reflection"]` every mirror; several tags find effects with all of them. `effectTags()` lists every tag with how many effects carry it, the most used first, and `effectTags(query)` the tags of the effects a query finds (`effectTags({ category: "fire" })`: the tags to narrow fire effects by). Tags are written in kebab-case (`motion-blur`, `game-boy`); a query's tags are matched in any case, with spaces as hyphens. Image effects default to built-in sample pictures, so they look right before you set `uImage` to your own URL.

#### What an effect takes

`effectInputs(effect)` says what you can give an effect and how it answers the pointer, worked out from the effect itself:

```ts
import { effectInputs, findEffects, getEffect, textImage } from "@pixerate/flair/catalog";

effectInputs(getEffect("image-duotone")!);
// { accepts: ["image", "video", "svg"], images: [{ name: "uImage", wants: "picture" }], video: "filter", interactions: [], transparent: false, … }
effectInputs(getEffect("typewriter")!);
// { accepts: ["text"], texts: [{ name: "text", holds: "copy" }, { name: "font", holds: "font" }], interactions: [], … }
effectInputs(getEffect("click-ripple")!).interactions; // ["click"]

findEffects({ accepts: ["video"] }); // effects that run on video
findEffects({ accepts: ["text"], kind: "vector" }); // animated titles and labels
findEffects({ accepts: ["image"], interaction: ["hover"] }); // pictures that react to hovering
findEffects({ transparent: true }); // overlays to lay over a page, picture or video
```

- `accepts`: `image` (any picture URL), `video` (a live `<video>`, with `setLiveSource`), `svg` (an SVG URL, drawn with its transparency), `text` (words for a text control, or for a text mask through `textImage("…")`), `mask` (a shape with transparency whose silhouette the effect uses: an icon, a logo, a word), `path` (SVG path data for a shape control), `audio` (sound it reacts to, from reading `iAudio`, `iSpectrum` or `iBeat`).
- `images`: each image control's name, and whether it `wants` a `picture`, a `mask` or `text`.
- `texts`: each text control's name, and whether it `holds` `copy`, a `font`, a `path` or `glyphs`.
- `interactions`: `hover`, `press`, `click`, `trail` (follows where the pointer has been), `pointer` (follows where it is) or `scroll` (follows the page's scrolling), from the pointer and scroll built-ins a shader reads or a vector effect's `trigger`.
- `transparent`, `video` and `trigger`, as on the effect.

`findEffects` filters on `accepts` (all of them), `interaction` (any of them; `[]` for effects that don't answer the pointer) and `transparent`, and the `catalog.search` command takes the same filters and lists each effect's `accepts` and `interactions`. The `interactive` tag is kept in step with `interactions`.

#### Put an effect on a page

`@pixerate/flair/embed` pairs a catalog effect with what it takes and runs it, shader or vector, in one call. `mountEffect(host, effect, { subject })` takes a subject:
- `{ image }`: a picture's URL.
- `{ video }`: a playing `<video>`, shown live.
- `{ svg }`: an SVG, as markup or a URL.
- `{ text }`: words, typed into a vector effect, or drawn with `textImage` for a shader's text or mask.
- `{ path }`: path data.
- `{ audio }`: sound for an audio-reactive shader: a playing `<audio>` or `<video>` (still heard), a microphone's `MediaStream` (not played back) or a Web Audio node.

It puts the subject in the right control (see `effectInputs`) and throws a sentence if the effect can't take it.

```ts
import { mountEffect } from "@pixerate/flair/embed";

mountEffect(el, "image-duotone", { subject: { image: "/team.jpg" }, preset: "Spotify" });
mountEffect(el, "crt", { subject: { video: document.querySelector("video")! } });
mountEffect(el, "neon-outline", { subject: { svg: logoMarkup } });
mountEffect(el, "typewriter", { subject: { text: "Hello there" } });
mountEffect(el, "transition-wipe", { subject: [{ image: "/a.jpg" }, { image: "/b.jpg" }] });
mountEffect(el, "spectrum-bars", { subject: { audio: document.querySelector("audio")! } });
mountEffect(el, "scroll-draw"); // scroll effects follow the page by themselves
const m = mountEffect(el, "click-ripple"); // overlays get a transparent canvas, interactive effects answer the pointer
m.setValues({ uSpeed: 2 });
m.dispose();
```

`subjectValues(effect, subject)` gives the control values (and live sources) without mounting anything, for `ShaderRenderer`, `ShaderFrames` or `renderVectorEffect`.

In React, `<FlairEffect effect="image-duotone" subject={{ image: "/team.jpg" }} style={{ aspectRatio: "16 / 9" }} />` (from `@pixerate/flair/react`) does the same. In Svelte, use `<div use:flairEffect={{ effect, subject }}></div>` (from `@pixerate/flair/svelte`). Either way the effect fills its element, so size it with CSS.

Effects that show a picture (image, transition, morph, time-warp and the like) take transparent pictures too, such as SVG icons (Lucide and similar sets draw black `currentColor` strokes on a clear background). They lay the picture over a backdrop: `uBackdrop` (white by default) shows through its clear parts. Set `uBackdropAlpha` to 0 to keep the picture's alpha instead, and render with `{ alpha: true }` to lay the result over the page (`mountEffect`, `recordEffect`, `exportEffect` and `effectStack` do this for you). `SAMPLE_IMAGES.icon` is a Lucide-style sample icon. SVGs are rasterised at 2048 px on the long edge, so icons stay sharp.

#### Recording an effect

`recordEffect(effect, options)` (from `@pixerate/flair/embed`) records a catalog effect, applied to a subject, to a file in the browser, with no server and no extra dependencies:

```ts
import { recordEffect } from "@pixerate/flair/embed";

const mp4 = await recordEffect("image-duotone", { subject: { image: "/team.jpg" }, preset: "Spotify" });
const webm = await recordEffect("crt", { subject: { video }, format: "webm", duration: 5 });
const music = await recordEffect("spectrum-bars", { audio: "/song.mp3", duration: 10 }); // the sound drives it and is muxed in
const gif = await recordEffect("typewriter", { subject: { text: "Hello there" }, format: "gif", width: 640, height: 360, fps: 25 });
const overlay = await recordEffect("click-ripple", {
  format: "webm",
  alpha: true,
  pointer: { clicks: [{ x: 640, y: 360, time: 0.2 }] }, // or (t) => ({ pointer: [x, y, hover, press] })
  onProgress: (f) => (bar.value = f),
});
download(mp4); // a Blob
```

- **Formats.** `mp4` (H.264) or `webm` (VP9, else VP8) are encoded with WebCodecs and written by small built-in muxers: a faststart MP4 (`moov` before `mdat`) and a WebM with no `Cues`. `gif` uses gifenc. `png` gives a ZIP of numbered frames (`frame-0001.png`, …), so every format is one `Blob`. The default is `mp4` where the browser encodes H.264, else `webm`. When the browser can't make a format, it rejects with a sentence that names the formats that would work.
- **Exact frames.** Frame `i` is drawn at `start + i / fps` off screen, so the result is the same whatever the page is doing. Shaders render with `ShaderFrames`. A `<video>` subject is paused and sought to each frame's time, then put back. A canvas subject is drawn as it is, so draw it for each frame in `beforeFrame(time)`. Vector effects are drawn with `svgView` and rasterised.
- **Defaults.** 1280 × 720 at 30 fps. The length is a shader's `loop`, or a vector effect's picture plus its `hold`, else 4 s. The bitrate is `width × height × fps × 0.15`. Video sizes round up to even numbers. `recordingPlan(effect, options)` tells you what a recording will be (format, size, frames, encoder) before any frame is drawn.
- **Interaction.** Shaders that answer the pointer play their idle demo unless `pointer` scripts it, with the same `pointer`, `clicks` and `trail` that `ShaderFrames.render` takes. Click-triggered vector effects take `steps` (ms). Scroll effects play their idle demos too.
- **Sound.** `audio` takes a decoded `AudioBuffer` or an audio file's URL (fetched and decoded at 48 kHz). Audio-reactive shaders follow it frame for frame: each frame's `iAudio`, `iSpectrum` and `iBeat` come from `analyseAudioBuffer` at that frame's time, so the same file always makes the same video. The stretch from `start` to `start + duration` becomes the video's sound track: AAC in an `mp4`, Opus in a `webm` (encoded with WebCodecs' `AudioEncoder`, muxed by the same built-in muxers). Where the browser has no AAC encoder, the default format falls back to `webm`, and an explicit `mp4` is refused with a sentence. Pass `audioTrack: false` for the picture alone. `gif` and `png` have no sound, so there the audio only drives the picture.
- **Motion blur.** `shutterAngle` (degrees, 0 to 360; default 0, off) blurs movement as a film camera does: the shutter is open for `(shutterAngle / 360) / fps` seconds from each frame's time, and the frame is the average of `shutterSamples` pictures (2 to 32, default 8) drawn at the middles of that time's slices. 180 is a film camera's usual. Pictures are averaged in premultiplied alpha, so transparent recordings get no dark fringes. The pointer, the sound, a `<video>` subject and `beforeFrame` are all taken at each sub-frame's time, and recording takes `shutterSamples` times as long. Out-of-range values are refused with a sentence naming the range. `checkShutter`, `shutterTimes` and `FrameAverager` are exported for frames of your own.
- **Transparency.** `alpha` defaults to `drawsAlpha(effect, values)`: true for an overlay (`transparent`) unless its `uBackgroundAlpha` is turned up to 1 (`sparkles` with its "With background" preset records an opaque mp4), and for a picture effect whose `uBackdropAlpha` is below 1. It is kept in `webm` (VP9/VP8 with an alpha channel, encoded as a second stream and stored as `BlockAdditions`, as Chrome does), in `png`, and in `gif` (one see-through colour, so edges are hard). An `mp4` has no alpha, so asking for both is refused. When alpha is off, transparent pixels are laid over `background` (black for shaders, white for vector effects).

Limits: video needs WebCodecs (Chrome and Edge 94+, Safari 16.4+ for H.264, and Firefox 130+). Safari doesn't play alpha WebM, so use PNG frames there. Everything is held in memory until the end, so record long or 4K clips in parts. Vector effects are rasterised once per frame, which is slower than shaders. A picture from another site needs CORS, as on screen.

#### Effects on video

Image controls can show a playing `<video>` (or a canvas) instead of a picture. `setLiveSource(name, video)` puts it in the control named `name`. The video's current frame is uploaded each time it changes, and a paused preview still follows the video. The renderer never plays, seeks or loops the video itself. The control's value keeps its URL, so documents, presets and agents still see a plain string.

```ts
const crt = getEffect("crt") as ShaderEffect;
const video = Object.assign(document.createElement("video"), { src: "/clip.mp4", muted: true, loop: true, crossOrigin: "anonymous" });
await video.play();
const preview = new ShaderRenderer(host);
preview.setSource(crt.source);
preview.setLiveSource("uImage", video); // null goes back to the URL
```

Each shader with an image control has a `video` field that says how it suits video:

- `filter`: treats each frame on its own, so it works as a live filter (CRT, film look, duotone, glitch, ASCII and others).
- `transition`: blends two pictures, so it works between two clips (put one video in `uFrom` and one in `uTo`).
- `interactive`: reacts to the pointer, and works over video too (magnifier, hover reveal and others).
- `stills`: runs on video but is made for a still picture. Time-warp effects move the picture to fake motion of their own, and the morph effects need shapes in fixed places. To retime real footage, use the timing effects (below).
- `none`: its picture is rendered text or a silhouette mask.

`findEffects({ video: ["filter", "transition"] })` lists the effects that suit video. The `catalog.search` command takes the same filter.

A video from another site needs `crossOrigin = "anonymous"` and that site's CORS consent. Without it, the control shows black and `onImageError` explains why. For frame-exact output, step the video with `ShaderFrames`: pause the video, then for each frame `await seekVideo(video, t); frames.render(t)`. Both `ShaderRenderer.ready()` and `ShaderFrames.ready()` wait for each live video's first frame.

#### Retiming video: timing effects

Timing effects (`kind: "timing"`, category `timing`) retime footage. A shader sees one picture at one time, so these are not shaders. Each is a pure function that, for every moment of the result, names the footage frames to show, with weights, and how to blend them (`average`, or `lighten` where the brightest wins). Any frame can be drawn on its own, in any order, and only the footage it needs is decoded.

| Effect | What it does |
| --- | --- |
| `retime-speed` | Slower or faster throughout. Slowed, it blends the frames either side; sped up, it averages the frames it passes over. |
| `retime-ramp` | Eases from full speed into slow motion round one moment and back out, like a sports replay. |
| `retime-reverse` | Plays backwards. |
| `retime-boomerang` | Forwards then backwards, `loops` times, sped up. |
| `retime-freeze` | Stops on one frame, holds it for `hold` seconds, and plays on. |
| `retime-stutter` | Replays short snatches a few times before moving on. |
| `retime-step` | Holds each frame at a low frame rate, for a stop-motion look. |
| `frame-echo` | Each frame with fading copies of the frames just before it. |
| `long-exposure` | A shutter held open for `exposure` seconds. Averaged, water turns silky and crowds melt away. With `lighten`, lights draw streaks. `build` keeps the shutter open from the start, and `fade` dims older frames. |

```ts
import { mountEffect, recordEffect } from "@pixerate/flair/embed";
import { getTimingEffect, timingLength, timingSample } from "@pixerate/flair/catalog";

mountEffect(host, "long-exposure", { subject: { video }, preset: "Light trails" }); // without a subject, a preview clip of Flair's own
const mp4 = await recordEffect("retime-ramp", { subject: { video }, preset: "Sports replay" }); // as long as the retimed clip

const longExposure = getTimingEffect("long-exposure")!;
timingLength(longExposure, 6000); // ms of the result for 6 s of footage
timingSample(longExposure, { time: 2000, footage: 6000 }, { exposure: 1 });
// { frames: [{ time: 1000, weight: 1/31 }, …, { time: 2000, weight: 1/31 }], blend: "average" }
```

`timingSample` holds times within the footage, snaps them to its frames (`fps`, default 30), merges repeats, caps a moment at `MAX_TIMING_FRAMES` (128, about 4 s at 30 fps; longer exposures take evenly spaced frames) and makes the weights add up to 1. `TimingRenderer` draws a moment from any `TimingFootage`: a size, a length and a `frame(ms, out)` that writes RGBA. It keeps the frames it read, so the next moment of a long exposure reads only what is new. `videoFootage(video, width, height)` (in `/embed`) makes footage from a `<video>`, and `previewFootage` makes Flair's preview clip, which shows its own time so a retime reads plainly. Blending runs on the CPU, so `mountEffect` previews at up to 640 pixels across.

For agents, `catalog.search` takes `kind: "timing"`, and the `catalog.timing` command gives a retime's length and the footage frames at given times. `effect.load` refuses timing effects. In a scene, a layer with a video subject takes one as its `timing` (see Layers and transitions, below). `flairEffects` offers them to `@pixerate/editor`'s editors through `timingLength` and `timingSample` (see 4b).

In Node, `exportEffect` (and `flair render <id> --video clip.mp4 -o out.mp4`) retimes a video file with no browser. ffmpeg decodes the clip once to raw frames in a temporary folder (`width × height × 4` bytes a frame, deleted afterwards). The output takes the video's own size and frame rate unless you set them, and lasts as long as the retimed clip. The clip's own sound would not follow a retime, so it is left out; pass `audio` (`--audio`) to mux another track. `shutterAngle` adds motion blur as usual.

#### Pixels in and out, and Web Workers

Image controls also take pictures that are not on the page: an `ImageBitmap`, a WebCodecs `VideoFrame`, an `ImageData` or an `OffscreenCanvas`. A canvas is uploaded on every frame; a still is uploaded once, so pass the next picture to `setLiveSource` before each frame that should show it (the same object again uploads its changed pixels). A `VideoFrame` stays yours to `close()` once the frame that shows it has been rendered.

`ShaderFrames` runs in a Web Worker as it does on a page. Give it an `OffscreenCanvas` (or let it make one where there is no `document`), and take each frame out with `readImageData()` (RGBA, 8 bits a channel, rows top down, sRGB, not premultiplied: an `ImageData`) or `await toImageBitmap()`, which a Worker can transfer to the page without copying. In a Worker, image URLs load with `fetch` and `createImageBitmap`. SVG URLs cannot be decoded there: rasterise them on the page and pass the bitmap.

```ts
// worker.ts
import { ShaderFrames } from "@pixerate/flair";
const frames = new ShaderFrames({ source, width: 1920, height: 1080, canvas: new OffscreenCanvas(1920, 1080) });
self.onmessage = async ({ data: { time, frame } }: MessageEvent<{ time: number; frame: VideoFrame }>) => {
  frames.setLiveSource("uImage", frame);
  frames.render(time);
  frame.close();
  const bitmap = await frames.toImageBitmap();
  self.postMessage(bitmap, [bitmap]);
};
```

The demo's `#pixels` page checks that each kind of picture arrives the right way up, on the page and in a Worker, and times a 1080p frame rendered and read out each way.

#### Effect stacks and feedback

`ShaderPipeline` renders several shaders as one picture on one WebGL2 context. Each pass draws into a texture of its own, and the last pass is the output (on `canvas`, or from `readImageData()` / `toImageBitmap()`). A pass's image controls take their pictures from:

- `"previous"`: the pass before.
- `{ pass: n }`: another pass's output (the frame before's, for a later pass).
- `"feedback"`: the pass's own last frame, for trails, echoes and anything that builds on itself.
- A picture, as with `setLiveSource`.

`blend: "over"` draws a pass over the one before by its alpha, for overlays. `effectStack` (from the catalog) turns catalog shaders into passes: each filter reads the layer below, and overlays are drawn over it.

```ts
import { ShaderPipeline } from "@pixerate/flair";
import { effectStack } from "@pixerate/flair/catalog";

const stack = new ShaderPipeline({ passes: effectStack(["aurora", "crt", "vignette-grain"]), width: 1280, height: 720 });
stack.render(2.5);

// A trail: each frame mixes the pointer's glow into the frame before.
const trail = new ShaderPipeline({
  passes: [{ source: `uniform sampler2D uLast; // @control filter=linear wrap=clamp
void mainImage(out vec4 c, in vec2 f) {
  vec4 last = texture(uLast, f / iResolution.xy) * 0.94;
  c = max(last, vec4(smoothstep(24.0, 0.0, distance(f, iPointer.xy))));
}`, inputs: { uLast: "feedback" } }],
  width: 640, height: 360,
});
```

With feedback, a frame depends on the frames before it, so render them in order from the start (or from `resetFeedback()`) to get the same frames every time. Each pass costs about one draw plus a mipmap; at 1080p, a three-effect stack measured within a millisecond of a single `ShaderFrames`.

##### Masks and regions

`setMask(mask)` (or the `mask` option) limits where a pipeline's effect applies, on the GPU.

- **Coverage** comes from a picture's alpha (or its luminance, with `channel: "luminance"`), stretched to the output.
- **A region** is a rectangle in output pixels from the top left, with a soft edge `feather` pixels wide. Given both, coverage is the picture's times the region's.
- **`invert`** turns coverage round.
- **Where coverage is 0, `under` shows.** That's usually the picture the effect changes, either given directly or as `{ pass: n }` for a pass's output. Without `under`, coverage multiplies the output's alpha instead, as for a generator laid over something else.

0 means untouched and 1 means the full effect, as with `@pixerate/editor/effects`' render `mask`.

```ts
const filtered = new ShaderPipeline({
  passes: effectStack(["crt"], { source: photo }),
  width, height,
  mask: { picture: selection, under: photo }, // the CRT look only where the selection is
});
filtered.setMask({ region: [40, 40, 320, 180], feather: 12, under: photo });
```

##### In a host's WebGL context

A compositor or editor that draws with WebGL2 can give the pipeline its own context (`gl`) and keep frames on the GPU, with no read back:

- The host's textures go into image controls as `{ texture, width, height }` (rows bottom up). They are copied at each render, and their own filtering is left alone.
- The output is `outputTexture`, ready to sample, or it can be drawn into a framebuffer of the host's with `render(t, { target })`.

After every call the pipeline leaves the host's state as it found it: framebuffers, viewport, program, texture units, vertex array, scissor, depth, stencil, culling, blending, colour mask, clear colour and unpack flags. `dispose()` frees only what the pipeline made. At 1080p, drawing a two-effect stack into a host framebuffer measured 0.5 ms a frame, against 6.7 ms to read it back and upload it again.

```ts
const pipeline = new ShaderPipeline({ passes: effectStack(["crt"]), width, height, gl: hostGl });
pipeline.setInput(0, "uImage", { texture: layerTexture, width, height });
pipeline.render(t, { target: hostFramebuffer }); // or sample pipeline.outputTexture
```

##### Float layers, colour and alpha

`format: "rgba16f"` or `"rgba32f"` makes every pass draw into float textures, for 16- and 32-bit layers and HDR. The default is `"rgba8"`. Float formats need `EXT_color_buffer_float`, and `"rgba32f"` also needs `OES_texture_float_linear`; without them the constructor says which to use instead. The contract:

- **Shaders see sRGB-encoded colour in every format**, as they are written, so an effect looks the same at any depth. In a float format, values keep their precision between passes and may go above 1 or below 0.
- **8-bit in and out** (`readPixels`, `readImageData`, pictures in image controls) are sRGB-encoded, with straight (not premultiplied) alpha, as `ImageData` is.
- **Float in and out** are in **linear light** (sRGB primaries), with straight alpha. Colour may exceed 1, the same as `@pixerate/editor/effects`' `EffectPixels.float`. A float picture `{ width, height, data: Float32Array }` (rows top down) goes into an image control like any other input. `readFloatPixels()` gives the output.
- **Conversion runs on the GPU**, with the sRGB curves extended past 0–1 (sign-preserving), so HDR survives: an output of 2.0 reads back as 4.95 in linear light.

Overlay shaders (`category: "overlay"`) have `transparent: true`: they write coverage to `fragColor.a` and draw nothing elsewhere, so render them with `new ShaderRenderer(host, { alpha: true })` (or `new ThumbnailPool({ alpha: true })`) and lay the canvas over a picture, video or page. Overlays with a background opacity control (`sparkles`, `bokeh`, `circular-spectrum`, `bass-pulse`, `vinyl`, `gemstone`, `chrome-text`, `floor-reflection`) draw on clear by default; their "With background" preset ("On the platter" for `vinyl`) or `uBackgroundAlpha: 1` gives them a full-frame background. Every other shader that paints a `uBackground` colour gets the same "Background opacity" control, at 1 by default so it looks as before: below 1 the background colour is keyed out of the frame (colour to alpha, `withBackgroundOpacity`), so a generator such as `neon-ripple` keeps its glow and hue and sits over whatever is under it. `drawsAlpha(effect, values)` says when an effect needs an `alpha` canvas. Some overlays are added light: give `glare-sweep`'s canvas `mix-blend-mode: plus-lighter` and it adds exactly (over `image-duotone`, that is the duotone with the gliding glare it used to have built in). Interaction effects answer the pointer. Interactive shaders read `iPointer` and `iClicks`, so they work in any `ShaderRenderer` with no wiring, and play an idle demo when nobody is pointing (turn off "Demo when idle" to stop it). Vector micro-interactions carry a `trigger`: pass it to the player, `new SvgPlayer(host, renderVectorEffect(effect), { trigger: effect.trigger })`. A hover or press trigger plays to the end while hovered or held and back again after; a click trigger plays the next step on each click, so toggles turn on and off. Hosts can drive them too, with `player.setActive(on)` and `player.advance()` (from a keyboard handler, say).

To morph between any two SVG shapes, `morphPaths(from, to)` (from `@pixerate/flair/vector`) returns two paths with one structure, so `attrs: { d: [a, b] }` blends them point by point: curves and arcs are read, pieces are paired by position and size, and a piece with no partner grows from or shrinks to a point (draw them with `fill-rule="evenodd"`). `morphSequence` does the same for three or more shapes. `feature-morph` morphs two photos from five matching points, and `silhouette-morph` morphs any two silhouettes or logos (or words, through `textImage`).

#### Motion primitives

`@pixerate/flair/motion` holds the motion vocabulary as data: reusable entrances, exits, emphasis and path motions that work on any element of an `SvgMotion`. Each primitive is a JSON descriptor (`id`, `kind`, `description`, `params` with labels, defaults, units and ranges, and a default `ms` and `ease`), so people and agents can list and describe them without running anything; the expansion behind each id is a pure function.

| Kind | Primitives |
| :--- | :--- |
| Entrance (600 ms, ease out) | `entrance.fade`, `.pop`, `.slap` (a sticker slapped down: big and turned, past full size, settling straight), `.grow`, `.slide` (direction, distance), `.wipe` (direction), `.iris` (circle or box), `.split` (horizontal or vertical), `.zoom`, `.rise`, `.draw` (outline on, then the fill) |
| Exit (450 ms, ease in) | `exit.fade`, `.shrink`, `.slide`, `.wipe` (a wipe in reversed), `.undraw` |
| Emphasis | `emphasis.pulse`, `.shake` (settles), `.teeter`, `.wave`, `.color-pulse`, `.spin`, `.wiggle` (seeded noise) |
| Path | `path.follow` (along a path id, `orient`, from/to fractions), `path.text` (a `<text>`'s words set along a `<path>` by id, moving from/to fractions of its length, `lift` off it) |

```ts
import { applyPrimitive, removePrimitive, PRIMITIVES } from "@pixerate/flair/motion";

let motion = { svg: '<svg viewBox="0 0 200 100"><rect id="card" x="10" y="10" width="80" height="40"/></svg>' };
const pop = applyPrimitive(motion, { primitive: "entrance.pop", target: "card" });
if (pop.ok) motion = pop.motion; // else pop.message says what to fix ("Did you mean …?")
const pulse = applyPrimitive(motion, { primitive: "emphasis.pulse", target: "card", delay: 800, params: { count: 2 } });
// pulse.tag ("emphasis.pulse@card") takes it off again: removePrimitive(motion, pulse.tag)
```

A use is checked whole (primitive, target id, params, timing) before anything changes, and applies all or nothing. The result is plain `SvgAnimation`s (tagged with the use) and, where needed, a wrapper group round the element (so uses stack: an entrance, emphasis and an exit each move their own group) or a clip path in the element's own box (wipes, irises and splits, so text needs no measuring). Primitives that scale or turn round the centre measure the element's box from the markup; give `box` (viewBox units) for text. Emphasis takes `repeat` and `alternate` too. Defaults match `@pixerate/editor`'s animation editor.

#### An animated SVG file

`svgAnimatedMarkup(motion, options)` (from `@pixerate/flair/vector`) writes any `SvgMotion` as one self-contained `.svg` that plays and loops on its own, with no script and no player: put it in an `<img src>`, open it as a file, or inline it. The changes are written as SMIL, so it needs no DOM to make:

```ts
import { effectDefaults, getEffect, renderVectorEffect, type VectorEffect } from "@pixerate/flair/catalog";
import { svgAnimatedMarkup } from "@pixerate/flair/vector";

const effect = getEffect("stat-counter") as VectorEffect;
const svg = svgAnimatedMarkup(renderVectorEffect(effect, effectDefaults(effect)), { hold: effect.hold })!;
img.src = `data:image/svg+xml,${encodeURIComponent(svg)}`; // or save it as stat-counter.svg
```

- **Options**: `hold` (ms on the last frame, default 600), `duration` (the loop, default the picture's length plus `hold`), `loop: false` to play once and stay on the last frame, `steps` (ms) for click-triggered effects, `fps` (default 30) for what is sampled, and `idSuffix`.
- **How it is written**: each attribute change is one `<animate>` (a `transform` is one `<animateTransform>` per function), and eases are exact `keySplines` (a cubic-bezier `ease` is written as given, unless it overshoots 0–1, which SMIL cannot spline, so it is sampled). Repeated cycles are written cycle by cycle (an alternating one with its spline turned round), a `strobe` as exact held frames, and a spring ease is sampled at `fps`. `draw` animates `stroke-dashoffset`, `along` becomes `<animateMotion>` on the path, `view` animates the `viewBox` (keeping `data-fixed` and `data-nonscaling` elements as the player does), and `solo` toggles `display`. Counts and written text are one `<tspan>` per text, shown in turn, sampled at `fps`. Every element starts on the first frame, so it still shows that where SMIL does not run.
- **Limits**: a count that changes faster than `fps` can be up to half a sample out. A change cut short by the next one, or a `matrix` transform, is sampled. A `view` that frames an element by id (it needs layout) is left out, as in `svgFrameMarkup`. Attributes SMIL cannot blend change in steps. Ids the picture refers to (gradients, filters, paths followed) get a suffix, a hash of the motion by default, so two files inlined in one page don't clash. `#id` selectors in a `<style>` are not renamed. Interaction triggers (hover, press, click) cannot be written as SMIL, so a click-triggered effect plays its `steps` on a timer.
- **Size**: catalog effects come out at 1 to 105 KB (`drip-text` is the largest).

### React

`@pixerate/flair/react` wraps the player, so a page needs no ref, effect or dispose of its own. `<VectorEffect>` plays a catalog vector effect by id, `<SvgPlayerView>` any `SvgMotion`:

```tsx
import { VectorEffect } from "@pixerate/flair/react";

<h1>
  Stop the <VectorEffect id="drip-text" values={{ word: "Slop", inline: true, font: "inherit" }} loop={false} />
</h1>;
```

- **Server rendering**: both render a still of the last frame as markup (`"first"` for hover and press triggers; set `poster` for another), sized from the viewBox, so the page hydrates with the picture in place. The `SvgPlayer` takes over after mount and is disposed on unmount.
- **Reduced motion**: under `prefers-reduced-motion: reduce` the still stays. `reducedMotion="always"` or `"never"` overrides it.
- **Size**: a block as wide as its container, with the viewBox's aspect ratio. With `inline` (or an effect whose `inline` control is on) it is an `inline-block` 0.72em high, sitting on the baseline like a capital letter; pass a CSS length to `inline` for another height. Add `contain` to keep room for what spills past the text (a margin of its overhang).
- **Plays when seen**: an effect that plays once (`loop={false}`, no trigger) waits until it is scrolled into view, so one further down the page doesn't finish before anyone sees it. Pass `playOnEnter={false}` to start at mount.
- **Props**: player options (`loop`, `autoplay`, `speed`, `hold`, `trigger`, `steps`, `pauseWhenHidden`, `playOnEnter`, `clock` …), `values` and `preset` for an effect, `onPlayer` for the player itself, and any `<span>` attribute (`elementId` sets the host's `id` on `<VectorEffect>`). Values are compared by content, so an inline object does not restart it; pass `<SvgPlayerView>` a memoised `motion`.

Without React or Svelte, `svgFrameMarkup(motion, { at: "last" })` (from `@pixerate/flair/vector`) gives the same still as safe `<svg>` markup with no DOM, for any server or framework.

### Svelte

`@pixerate/flair/svelte` does the same for Svelte 5, as plain TypeScript (no `.svelte` files, so nothing to compile). The `vectorEffect` action plays an effect by `id` (or any `motion`) in its element, and `vectorEffectStill` gives the server-rendered still:

```svelte
<script>
  import { vectorEffect, vectorEffectStill } from "@pixerate/flair/svelte";

  let { word = "Slop" } = $props();
  const params = $derived({ id: "drip-text", values: { word, inline: true, font: "inherit" }, loop: false });
  const still = $derived(vectorEffectStill(params));
</script>

<h1>Stop the <span use:vectorEffect={params} style={still.style}>{@html still.markup}</span></h1>
```

- **Params**: the React props, as one object: `id` with `values` and `preset`, or `motion`; player options; `poster`, `reducedMotion`, `inline`, `contain`, `onPlayer`. An effect that plays once waits until it is scrolled into view, as in React. A change remakes the player (values by content; `speed` without remaking), and it is disposed when the element goes.
- **Still**: `markup` is the still's layer and `style` the host's size from the viewBox, with the same rules as React. The action hides the still while the player runs and keeps it under `prefers-reduced-motion`. Without `vectorEffectStill` it makes its own still and sizes the element on the client.
- **Attachments**: `{@attach fromAction(vectorEffect, () => params)}`, with `fromAction` from `svelte/attachments`.

### Effects as UI components

Some vector effects are UI components in all but name, and say so: their metadata (`effectMeta(effect).ui`, `getEffectMeta(id).ui` from `/catalog/lazy`) and `flairEffects()`' summaries and descriptions carry a `ui` field, `@pixerate/schemas`' `UiDescriptor` (what component type it `implements`, its `contract`: props as JSON Schema, controlled `state` and `events`, `a11y`, `colorRoles`, `sizing`; the `platforms` it renders on; an `example`; and a `contentHash` that changes whenever its output does, so a sync can tell). Next to it, `uiBindings` says which controls the contract drives: `props` (prop → control), `colors` (colour role → colour control, e.g. `{ "track-on": "on", "track-off": "off", surface: "background" }`, so a theme restyles it by role) and `state` (`{ checked: { interaction: "click" } }`: a boolean the click steps flip). Effects without `ui` are not meant as UI. The hints are `UI_HINTS` in `@pixerate/flair/catalog` (and `/catalog/lazy`); so far `toggle-switch` (`switch`), `progress-bar` (`progress`) and `gauge` (`gauge`, a `data-visual`).

Hosts give them typed data and, for a switch, own its state:

```ts
import { mountEffect } from "@pixerate/flair/embed";

mountEffect(el, "gauge", { data: { value: 88, max: 160, unit: " km/h", label: "Speed" } });
const wifi = mountEffect(el2, "toggle-switch", {
  state: { checked: false },
  label: "Wi-Fi",
  onEvent: (event, { checked }) => save(checked).then(() => wifi.setState!({ checked })),
});
```

```tsx
const [checked, setChecked] = useState(false);
<FlairEffect effect="toggle-switch" state={{ checked }} onEvent={(_, d) => setChecked(d.checked as boolean)} label="Wi-Fi" />
<FlairEffect effect="progress-bar" data={{ value: 40, label: "Uploading" }} />
```

- **Data** fills the controls `uiBindings.props` names (`setData` merges new data in); a prop that is unknown, mistyped or out of range is refused with a sentence. `uiValues(effect, data)` gives the control values for `renderVectorEffect`. Plain `values` (the text controls) still work, under the data.
- **State**: given `state`, a click, Space or Enter fires `onEvent("change", { checked })` and nothing moves until the host passes the new state (`setState`, or the `state` prop/param); without it the switch flips itself and still fires `change`. `{ checked: true }` in `data` starts an uncontrolled switch on.
- **Accessibility**: the element gets the contract's `role`, `tabindex` when it has keys, `aria-checked`, `aria-label` (from the `label` prop, or the `label` option) and `aria-valuenow` / `aria-valuemax` / `aria-valuetext`.
- **Motion**: a component plays once to its rest point (`a11y.reducedMotionAt` of its play) and stays; under `prefers-reduced-motion` it shows that rest state still (`reducedMotion: "always"` or `"never"` overrides).
- The Svelte `flairEffect` action takes the same `data`, `state`, `onEvent`, `label` and `reducedMotion` params.

`shader-text` fills letters from a text image: set its `uText` control to `textImage("Your title", { weight: 900 })`, a transparent SVG `data:` URL of any Unicode text.

A vector effect declares its controls in its picture, the way a shader declares its uniforms: the first `{{name: type …}}` declares a control (`float`, `int`, `bool`, `color` or `text`, with `@control`'s attributes; quote values with spaces in single quotes), and every `{{name}}` is filled with its value. Declarations can sit in an XML comment, which is dropped when the picture is filled in, and text is escaped, so any words are safe:

```ts
const title = { motion: { svg: `<svg viewBox="0 0 200 60"><!-- {{title: text default='Hello' label='Title'}} {{ink: color default=#6366F1}} --><text x="10" y="40" fill="{{ink}}">{{title}}</text></svg>` } };
vectorControls(title.motion); // [{ name: "title", type: "text", default: "Hello", … }, { name: "ink", type: "vec3", color: true, … }]
renderVectorEffect(title, { title: "Fish & chips" }); // …<text …>Fish &amp; chips</text>…
renderVectorEffect(getEffect("drip-text")!, { word: "UNSTOPPABLE" }); // drips follow the word
```

### 2. Write your own shader

```glsl
// Controls are uniforms annotated on the same line.
uniform vec3 uTint;    // @control color default=#77C16A label="Tint"
uniform float uSpeed;  // @control min=0 max=4 default=1 label="Speed"
uniform sampler2D uPhoto; // @control filter=linear wrap=clamp label="Photo"

void mainImage(out vec4 fragColor, in vec2 fragCoord) {
  vec2 uv = fragCoord / iResolution.xy;
  vec3 photo = texture(uPhoto, uv + 0.01 * sin(uv.yx * 20.0 + iTime * uSpeed)).rgb;
  fragColor = vec4(photo * uTint, 1.0);
}
```

#### Paths

A `sampler2D` marked `path` is a path control: the effect draws along a path given at run time.

```glsl
uniform sampler2D uPath; // @control path default="M 10 80 C 40 10 65 10 95 80" fit=contain margin=0.1 label="Path"
```

Its value is SVG path data (`d`) or a list of points `[x0, y0, x1, y1, …]` in frame pixels from the top left (a painted stroke, a pointer's route). Path data is placed by `fit`: `contain` (the default) fits its bounds inside the frame, keeping `margin` (a fraction of the shorter side) clear; `cover` fills the frame; `none` reads it in frame pixels. Points are always pixels. The path is flattened, resampled evenly along its length (at most `MAX_PATH_POINTS`, 1024, points; longer paths are spaced further apart rather than refused) and packed into a small float texture, uploaded once per value. The fit happens in the shader, so the path follows resizes. `checkControlValue` refuses a value that is not a path, saying why, and `pathTexture(value)` / `pathPlacement(packed, width, height)` give the packed path and where it lands, for checking it without a GPU.

The catalog's GLSL helpers read it (`PATH` in `src/catalog/glsl.ts`, inlined into the effects that use it): `pathLength(path)`, `pathNearest(path, p)` (distance to the nearest point, how far along it is, which side `p` is on), `pathAt(path, along)` (the point and direction that far along) and `pathHits(path, p, radius, gap, from, to, hits)` (each pass of the path near `p`, for paths that cross themselves). `glass-tube` is built on them. Some effects draw their own shape until they are given a path (their path control defaults to `""`, no path): `border-beam` runs round any outline instead of its card border, `swoosh-underline` sweeps along any curve, and the pointer trails (`comet-trail`, `ribbon-trail`, `sparkle-trail`, `brush-trail`, `ghost-trail`, `light-painting`) follow a path while nobody is pointing, round a closed one or back and forth along an open one, so recordings can trace a route or a logo. These eight (the trails, `glass-tube` and `glass-writing`) size what they draw as a share of the frame unless `uUnit` ("Size unit", px) says otherwise: an editor painting one along a stroke sets `uUnit` from the brush's size, so a trail on a large canvas is as wide relative to the brush as it is in a small preview, while its positions stay in pixels. `findEffects({ accepts: ["path"] })` lists every effect that takes one, vector ones included (`scroll-draw`, `text-on-path`, `signature`, `route` and others, whose pictures fit the path).

Words become a path with `textPath(text, { font, size, align })` (from `@pixerate/flair/vector`): single-stroke handwriting, in `script` (joined up, the default) or `sans` (printed), each letter's strokes in the order a pen writes them, so a path effect writes the words on (`glass-writing`). It takes printable ASCII and line breaks, and refuses anything else, naming the letters (`textPathProblem`). In the editor, `values.set` turns `{"text": "…", "font"?, "align"?}` on a path control into that path data. The letters are the Hershey fonts (see `THIRD_PARTY_NOTICES.md`). In a control schema a path is a string with `format: "svg-path"` or an array of numbers; strict validators (Ajv's `strict: true`) need that format registered, for example with `pathProblem(d) === null`.

A declared `min=` or `max=` is a limit: `checkControlValue`, the editor's `values.set` and keyframes, and the CLI's `--set` refuse a number beyond it, naming the range. A control that declares neither keeps the default range (0 to 1, or 0 to 10 for `int`) for its slider, and takes any number.

```ts
import { ShaderRenderer, ShaderFrames, recordGif, standaloneHtml, parseControls } from "@pixerate/flair";

const status = renderer.setSource(source); // { ok, errors: [{ line, message }] }
parseControls(source); // [{ name: "uTint", type: "vec3", color: true, default: [...] }, ...]
const gif = await recordGif({ source, width: 480, height: 270, fps: 30, duration: 3 });
const frames = new ShaderFrames({ source, width: 480, height: 270, alpha: true }); // alpha: keep fragColor.a
frames.render(1.5);
frames.readImageData(); // or await frames.toImageBitmap()
const page = standaloneHtml("My effect", source, { uSpeed: 2 }); // { audio: "song.mp3" } or { audio: "mic" } for sound
```

### 3. Build an editor (any UI)

import { createEffectEditor, bindShaderRenderer, bindSvgView } from "@pixerate/flair/editor";

const editor = createEffectEditor({ from: "nebula" });

```

### 4. Let an agent drive it

This section is for agents running *inside* your app. For a coding agent writing your app's code, install Flair's [agent skills](#agent-skills) instead.

```ts
import { createEffectToolProvider, createEffectToolRegistry, toolDefinitions, callTool, EFFECT_AGENT_INSTRUCTIONS } from "@pixerate/flair/editor";

const tools = createEffectToolProvider(editor, {
  capture: () => renderer.capture({ type: "image/png" }), // adds a `view_effect` tool so the model can look
});

// Give your model EFFECT_AGENT_INSTRUCTIONS and toolDefinitions(tools), then for each tool call:
const result = await callTool(tools, call.name, call.input); // MCP tools/call result

// Or serve them through @pixerate/editor/tools' ToolRegistry (MCP tools/list and tools/call):
const registry = createEffectToolRegistry(editor); // registry.listTools(), registry.callTool(name, args)
```

The tools are `list_commands`, `run_command` and `run_commands`, plus `view_effect` when you can capture the preview. The commands they run:

- **Inspect and start:** `effect.describe`, `catalog.search` (`{ total, effects }`, each effect with its tags, 20 at a time unless you pass `limit`; `offset` pages on; filter by words, `category`, `group`, `kind`, `tags`, `video`, `accepts`, `interaction` and `transparent`), `catalog.tags` (`{ total, tags }`: the tags with how many effects carry each, 50 at a time, under the same filters; an unknown tag is refused with the nearest ones), `effect.load`.
- **Edit the effect:** `effect.setSource` for shaders (it returns the compile report when a preview is bound, or says the source has not been compiled yet), `effect.setMotion` for vector pictures.
- **Motion primitives** (vector pictures): `primitive.list` (by `kind`), `primitive.describe`, `primitive.apply` (returns the use's `tag` and the animations it added), `primitive.applied` and `primitive.remove`.
- **Values and presets:** `values.schema` (the JSON Schema of the effect's values), `values.set`, `values.reset`, `values.randomize`, `preset.apply` and `preset.save`. An image control that draws words from a `textImage` (a banner's or caption's `uText`, shown as `textMask: true` in `effect.describe`) takes the words themselves in `values.set` and `keyframe.set`: `{ "text": "GAME OVER", "font"?: "Georgia, serif", "weight"?: 400 }` becomes a text image in the default's font and weight unless you name others. A text image's URL still works; bare words are refused, since they would be read as a file path.
- **Keyframes:** `keyframe.set`, `keyframe.setTrack`, `keyframe.remove`, `keyframe.setEasing` and `keyframe.clear`.
- **Timeline:** `timeline.setTiming`, `timeline.play`, `timeline.pause` and `timeline.seek`.
- **History:** `history.undo` and `history.redo`.

Every change is one undo step, and refusals come back as messages the model can act on.

### 4b. Effects in `@pixerate/editor`'s editors

`@pixerate/editor`'s editors take an effects provider, and `flairEffects()` is Flair's. The editor never imports Flair; the host passes the provider in.

```ts
import { flairEffects } from "@pixerate/flair/integrations";

editor.setEffectsProvider(flairEffects());

const provider = flairEffects();
const [wipe] = await provider.search("wipe", { use: "transition" });
const renderer = await provider.createRenderer(wipe.id, { width: 1920, height: 1080 });
const frame = await renderer.render({ time: 0, progress: 0.5, inputs: { from: clipA, to: clipB } }); // { width, height, data }
```

- **Catalog.** Every shader and vector effect, the camera moves as `camera` effects, and the motion primitives as `motion` effects. Metadata comes from the lazy catalog; an effect's source loads when it is described or rendered.
- **Uses and inputs.**
  - Video filters (and stills and interactive effects over a picture) are `filter`, and read the input `source`.
  - Transitions read `from` and `to`. `progress` (0–1, default `time / duration`) drives them in place of their own clock.
  - Overlays, titles, generators and interactive effects follow from the catalog's categories and inputs.
  - Other image controls are optional inputs named after their uniform (`uMask`, `uText`); without one, the effect shows its own sample.
- **Values.** Controls come as a strict JSON Schema, with colours as `#rrggbb`. A bad value is refused with `invalid_values`.
- **Rendering.**
  - Shaders render through a `ShaderPipeline`, on a page or in a Worker, and take `ImageBitmap`, `VideoFrame`, `OffscreenCanvas` or `{ width, height, data, float? }` inputs.
  - At `depth` 16 or 32 they render in half or full floats and also return `float` (linear light, straight alpha, as the contract defines it). Where the GPU cannot render to floats, frames are 8-bit and `depth` says so.
  - A `mask` is composited on the GPU over the untouched input (`source`, or a transition's `from`). With no input, coverage multiplies alpha.
  - Vector effects render on a page. In a Worker, pass `rasterizeSvg` or use `applyVectorEffect`. Their masks multiply alpha.
- **Vector.** `applyVectorEffect(id, target, values)` returns a vector effect's own animated SVG with its values filled in, or applies a motion primitive to the target's elements: `nodeIds`, or each top-level element with an id.
- **Authoring.** `capabilities.supportsAuthoring` is true, so the editor's Effect Authoring tab and its `effect_authoring_*` agent tools edit Flair effects through `openAuthoring`, which wraps Flair's own `EffectEditor` (it loads with the first session).
  - Shaders open with their GLSL (`sourceLanguage: "glsl"`). `setSource` compiles straight away, so errors come back with their lines in the source even before a preview exists; a `// @control` uniform added to the source becomes a control.
  - Vector effects open with their controls, keyframes and presets, without source (`sourceLanguage: null`). Their preview needs a page, or `rasterizeSvg` in a Worker. Motion primitives cannot be authored.
  - `exportDocument()` keeps Flair's own document in `flair`, so the source survives `openAuthoring({ document })`.
- **Camera.** `capabilities.supportsCamera` is true. Camera moves have the use `camera` and say their role (`transition` into a shot, or `hold` while it holds), length and cut. `cameraView(id, { from, to, u, ms, stage }, values)` gives the view a scene's camera has `u` of the way through the move, exactly as Flair's scene player moves it, motion blur included. `sampleCameraMove` keys a move for an editor to bake, with two keys at a cut. Camera moves draw no picture, so `createRenderer` refuses them; for an editor older than 0.224, pass `kinds: ["shader", "vector", "motion"]`.
- **Timing.** `capabilities.supportsTiming` is true (editors from 0.254). Timing effects have the use `timing`, no inputs and no duration. `timingLength(id, footageMs, values)` gives how long the retime lasts, and `timingSample(id, { time, footage, fps }, values)` gives the footage frames one moment shows, with their weights and blend. Both are synchronous and exactly what Flair's own players draw. The editor decodes and blends the frames from its own footage, so `createRenderer` refuses them; for an editor older than 0.254, pass `kinds: ["shader", "vector", "motion", "camera"]`.
- **Paint.** `capabilities.paintHints` is true: effects that make good paint in an editor that brushes with effects (the editor's effect paint) carry a `paint` hint on their summaries and descriptions, and the rest are not meant as paint (scenes and objects, loaders, UI, text and titles, banners, audio visualisers, cursor and click effects). `map` is `path` (the effect draws along the stroke, given its centreline as the path control), `stroke` (rendered into a strip bent along the stroke, with `repeat`: `repeat`, `mirror` or `clamp`) or `canvas` (fixed to the canvas, uncovered by strokes); `colors` are up to two colour controls the brush's colours fill, main first; `values` go over the defaults when painting (a clear backdrop, no draw-on); `live` says whether a stroke keeps playing; `size` is a suggested brush width when there is one. The hints are `PAINT_HINTS` in `@pixerate/flair/catalog` (and `/catalog/lazy`, and `EffectMeta.paint`).

  ```json
  { "map": "stroke", "colors": ["uLava", "uHot"], "values": {}, "live": true, "repeat": "mirror" }
  ```
- **UI components.** `capabilities.uiHints` is true: effects that work as UI components carry `ui` (`@pixerate/schemas`' `UiDescriptor`, with a `contentHash`) and `uiBindings` (which controls its props, colour roles and state drive) on their summaries and descriptions, and the rest are not meant as UI. See [Effects as UI components](#effects-as-ui-components).
- **Templates.** `capabilities.supportsTemplates` is true (editors from 0.233 use it). `listTemplates` and `describeTemplate` give Flair's sequence templates and their slots, shaped for a form. `instantiateTemplate(id, values, { name })` fills one and returns an `EffectSequence`: each shot's framing (where Flair's camera settles, dynamic framings worked out), its camera moves, its catalog effect layers and its transition. Values that do not fit are refused all at once, and subject slots left for the host come back in `openSlots`. What a sequence cannot carry (custom shader layers, element commands, behaviors, camera angles, effects left out by `kinds`) is dropped and named in `notes`, along with `validateScene`'s issues.

```ts
const session = await provider.openAuthoring({ effectId: "aurora", preset: "Ember" });
const { issues } = await session.setSource(edited); // [{ message, line, severity: "error" }] when it does not compile
session.setValue("uSpeed", 1.2, { gesture: "speed-drag" }); // one undo step for the whole drag
session.setKeyframe("uGlowA", 2000, "#ff6b6b", "ease-in-out");
const preview = await session.createPreview({ width: 480, height: 270 });
const frame = await preview.render({ time: 1000 }); // keyframed values at 1 s
const saved = session.exportDocument(); // JSON; reopen with openAuthoring({ document: saved })
```

The demo's `#provider` page runs the editor's own conformance check (`checkEffectProvider`) over every effect on your GPU, and draws a few through the contract.

### 5. Let an agent direct a scene

Scenes have their own tools, `FLAIR_AGENT_TOOLS` (Anthropic-style `{ name, description, input_schema }`), applied by a pure state machine:

```ts
import { FLAIR_AGENT_TOOLS, applySceneTool } from "@pixerate/flair";

let scene = initialScene;
// Send FLAIR_AGENT_TOOLS to your model, then for each tool call:
const result = await applySceneTool(scene, call.name, call.input);
if (result.ok) scene = result.scene; // keep the new state
reply(call.id, result.output); // send the model only `output`
```

The tools are `get_scene` (the scene, or with `view: "outline"` just its structure: each shot's layers, transition and the slots the host fills), `write_scene`, `update_shot`, `insert_shots`, `delete_shots`, `set_rig_widget`, `find_layer_effects` (catalog effects for a shot's layers, a layer's `timing` or its transition, with where each goes, what it takes as a subject, its controls and presets, a page at a time), `retime_layer` (sets or removes the timing effect that retimes a layer's video: slow motion, a ramp, a reverse, a freeze, a long exposure…), `find_camera_moves` (the camera moves a shot can use, with their controls), `find_templates`, `describe_template` and `use_template` (start the scene from a [sequence template](#-sequence-templates), filling its slots), `preview_scene` (a headless run: length, warnings, notes), `export_scene` (the scene as a text template, Lottie, Motion, FCP7 XML or an EDL: the model gets a summary, its notes and the template's editable fields; the file is in the result's `export` for the host to keep) and `batch_scene`, which runs several of them as one all-or-nothing change and lets a step use an earlier step's result (`"$1.output.outline.shots[0].hold"`).

Arguments are checked against each tool's schema, and a call that cannot apply (a shot that does not exist, an unresolved reference) is refused with `ok: false` and a sentence saying what to fix, leaving the scene as it was. Edits that apply return the scene's validation issues (unknown shot fields, an unknown effect with the nearest ids, a subject an effect does not take, a transition used as a layer, presets and control values checked against the catalog) so the model can correct them. `output` keeps replies small: an edit returns a one-line summary and the issues, not the whole scene.

## 🎞️ Layers and transitions

A shot arranges **catalog effects as layers** over its board, and can name a **catalog transition** into it:

```json
{
  "title": "Compute",
  "transition": { "effect": "transition-film-burn", "ms": 900 },
  "run": [{ "type": "element", "element": { "id": "card", "type": "rectangle", "x": 900, "y": 400, "width": 500, "height": 280 } }],
  "layers": [
    { "id": "sky", "effect": "aurora", "role": "background", "until": { "shots": 3 } },
    { "effect": "image-duotone", "preset": "Spotify", "subject": { "slot": "productShot" }, "rect": { "x": 1450, "y": 400, "width": 280, "height": 280 } },
    { "effect": "tick-ring-burst", "ids": ["card"], "padding": 60, "role": "overlay" },
    { "effect": "lower-third", "role": "overlay", "values": { "name": "Ada Lovelace" }, "from": 300, "fade": 200 }
  ]
}
```

- **What it draws:** a catalog shader or vector effect (`effect`, with `preset` and `values`), a custom shader (`source`: GLSL with `mainImage` and `// @control` uniforms), or a bare picture (only a `subject`).
- **On what:** `subject` is `{ image }`, `{ video }` (a URL), `{ svg }`, `{ text }`, or `{ slot: "name" }`, which the host fills when it plays or records the scene: `playScene(scene, board, clock, { subjects: { productShot: { video: videoEl } } })`, `recordScene(scene, { subjects })`, `standaloneSceneHtml(scene, { subjects })`, `flair scene html --subject productShot=./shot.mp4`.
- **Retimed video:** a layer whose subject is a video (`{ video }`, or a slot the host fills with one) takes a timing effect as its `timing`: an id (`"timing": "retime-reverse"`) or `{ "effect": "long-exposure", "preset"?, "values"? }`. The player draws the footage frames the effect picks for each moment, blended (`TimingRenderer`), and loops the retimed clip while the layer shows; any `effect` on the layer is applied to the retimed picture. `{ "subject": { "video": "surf.mp4" }, "timing": { "effect": "retime-speed", "preset": "Slow motion" } }` plays a clip at quarter speed with blended in-between frames. Timing effects ids are refused in `effect`, and a `timing` on a still subject is refused, each saying what to write instead. The plan carries it as the layer's `timing` (`{ effect, values }`, every value worked out). Blending runs on the CPU, so a retimed layer is drawn at up to 1280 pixels on its longer side. The scene tool `retime_layer` sets or removes it, and `find_layer_effects` with `kind: "timing"` lists the timing effects.
- **Artwork from a library:** `subject` can also be `{ asset: "provider:id" }`, artwork from the host's own library (a sticker pack, a brand kit, a user's uploads). Flair knows no library: the host passes a `resolveAsset(ref)` that returns `{ svg }` or `{ image }` (or `undefined` for a reference it does not have) to `scenePlan`, `mountScene`, `recordScene` and `standaloneSceneHtml`, and to `applySceneTool` as its fourth argument (`{ resolveAsset }`). `resolveSceneAssets(scene, resolveAsset)` swaps the artwork in and lists what did not resolve; an unresolved asset is a note in the plan, an issue for an agent, and draws nothing. Without a resolver, the scene tools refuse an edit that adds an asset. `mountEffect(el, "sticker-cutout", { subject: { asset: "acme:heart" }, resolveAsset })` works the same way for a single effect (`ready()` waits for the artwork), and `resolveSubject(subject, resolveAsset)` resolves one ahead of time.
- **Where:** without `rect` or `ids` a layer fills the screen; with them it sits on the board and moves with the camera (`ids` follow their elements, a path behavior included). `role` orders the stack: `background` under the board's elements, `subject` on the board over them (the default when placed), `overlay` above everything but the title and caption.
- **When:** `from` and `until` are ms after the shot starts, or `{ "shots": n }` for the start of the n-th shot after it. By default a layer lasts until the next shot. `opacity` (0–1) and `fade` (ms in and out).
- **Transitions:** `transition.effect` is a catalog transition (`findEffects({ video: ["transition"] })`; the scene tool `find_layer_effects` with `transition: true`). The last shot's final frame is its `uFrom`, the new shot its `uTo`, and `uProgress` runs 0 to 1 over `ms` (800 by default). With no camera `in` the camera cuts and the transition does the move; with one, both play together.
- **Copies and paths:** a run command `{ "type": "replicate", "element": {…}, "pattern": "grid" | "line" | "circle" | "spiral", "count": 8, … }` draws copies `<id>_0…` (`sequence.delayPerItem` staggers them through the hold), and a behavior `{ "type": "path", "target": "card", "waypoints": [{ "point": [x, y], "inTangent"?, "outTangent"? }, …], "orient"? }` moves an element along a curve at an even speed while the shot holds.

`validateScene` checks all of it (with the nearest effect ids, the subjects an effect takes, the elements there are), and `checkSceneLayers(scene)` checks presets and control values against the catalog, which it loads on demand. `playScene` tells a board which layers show at every step (`board.setLayers(layers, ms)`, bottom of the stack first) and which transition plays (`board.setTransition`).

**Playing and recording.** `scenePlan(scene)` works a scene out into a `ScenePlan`: plain JSON with each shot's timing, the camera at every frame, every element as it changes, and each layer and transition with its shader source or vector picture and its values. It holds no code and needs no catalog, so any player can draw it (its JSON Schema is `@pixerate/flair/schemas/scene-plan.json`; a native player would compile the GLSL ES 3.00 shaders for its GPU). In the browser (`@pixerate/flair/embed`):
- `mountScene(host, scene, { subjects })` plays it in a page.
- `recordScene(scene, { subjects, format, fps, width, height })` records it as `recordEffect` records an effect: MP4, WebM, GIF or PNG frames, frame-exact.
- `SceneCompositor` draws a plan at any time onto a canvas, for players of your own.

`standaloneSceneHtml(scene, options)` (async) is a page with the plan and the compositor in it, carrying only the effects the scene uses.

**Exporting.** The exporters carry what their formats can and name the rest (`sceneExportNotes(scene, format)`, written into each file and printed by `flair export`): Lottie takes picture layers as image layers and transitions as markers; Motion and FCP7 XML take every layer as a placeholder with its place and time (FCP7 on tracks above the shots, with each transition a cross dissolve); the EDL takes transitions as dissolve events and layers as comments. `await exportScene(scene, format, { frameRate })` exports to any of them by name (`SCENE_EXPORT_FORMATS`), as `flair scene export --format` and the `export_scene` agent tool do.

**Text templates.** `await exportTextTemplate(scene, { frameRate })` exports the scene's words as an animated title template for video editors: the Lottie animation with an editable text layer (`ty: 5`) for each shot title and caption (styled and placed as the player draws them), each element's text (hanging off its shape layer) and each layer with words (a text subject, or a vector effect's text controls, from a slot, its values, its preset or its defaults), and alongside it `fonts` (also the animation's `fonts.list`), `texts` (each one's font family, weight, size, tracking and line height, fill, alignment, an estimated box in stage px, in and out frames, and `segments`: its words' timings) and `fields`, what a template user fills. Each text document has a `sid` naming its Lottie slot in the animation's `slots` (Lottie 5.12), and a scene slot (`{ "slot": "headline" }`) is one field however many layers show it. Effects paced by a "Ms per word" or "Ms per letter" control get a timing a word, revealed in turn by a word range selector; their own look, lead-in and easing are not carried, and the notes say so. Boxes come from a width estimate, not measured fonts, and effect layers' words are fitted to the layer's box.

```bash
npx flair scene export ./scene.json --format text-template -o title.json
```

**Moving from scene media and effects:** `Scene.media`, `Shot.effects` and `Shot.stopEffects` were replaced by layers, and `validateScene` says what to write for each:

| Before | Now |
| --- | --- |
| `"media": { "plasma": { "type": "shader", "source": "…" } }` and `{ "type": "media", "media": "plasma" }` | `{ "layers": [{ "id": "plasma", "source": "…", "role": "background" }] }` on the shot that shows it |
| `{ "type": "glow", "ids": ["card"] }` (and the other built-in types) | a catalog effect: `{ "effect": "glow-ring-pulse", "ids": ["card"] }`; `find_layer_effects` finds one |
| `"stopEffects": ["glow"]` | the layer's `"until": { "shots": n }` (or ms) |
| rig target `media.plasma.speed` | `layers.plasma.speed` |
| `standaloneSceneHtml(scene)` | `await standaloneSceneHtml(scene)` |
| the `set_media` scene tool | `update_shot` with `layers` |

## 🧩 Sequence templates

A template is a scene with declared **slots** that a person or an agent fills to get a finished scene. Slots are typed (`image`, `video`, `svg`, `text`, `color`, `number`), each with a label, a default and, where it makes sense, a range (`min`/`max`, `integer`) or a `maxLength`. Subject slots are the layer slots scenes already have (`"subject": { "slot": "product" }`); the others fill `{{name}}` placeholders in any of the scene's strings (titles, captions, layer and transition `values`, element text), the way vector effects fill `{{control}}`. A string that is just `"{{holdMs}}"` takes the slot's typed value, so `"hold": "{{holdMs}}"` is a number.

```ts
import { instantiateTemplate } from "@pixerate/flair";
import { sceneTemplate } from "@pixerate/flair/catalog";

const result = instantiateTemplate(sceneTemplate("product-reveal")!, {
  product: "https://example.com/mug.png", // or <svg> markup, a data: URL, or { slot: "product" } to leave it for the host
  productName: "Orbit Mug",
  accent: "#2266FF",
  holdMs: 2600,
});
if (result.ok) play(result.scene);       // result.issues: validateScene's; result.openSlots: slots the host still fills
else console.warn(result.errors);         // e.g. 'Slot "holdMs" takes a whole number from 1200 to 6000; 99 is out of range.'
```

`instantiateTemplate` is pure and never changes the template. It refuses an unknown slot, a value of the wrong type and one out of range, all at once, each with what the slot takes. Slots left out take their defaults; the catalog's subject slots default to a labelled placeholder picture, so every template plays as it is. `checkTemplate(template)` checks one of your own: its slots and defaults, placeholders and layer slots it does not declare, slots it never uses, and its scene with the defaults filled in.

The catalog's templates (`SCENE_TEMPLATES` in `@pixerate/flair/catalog`; the root loads them on demand) are built only from catalog effects, camera moves and transitions:

| Template | What it does |
| --- | --- |
| `product-reveal` | A product shot drifts in over a gradient, the camera punches in to a lower third with its name and price, and a flare wipes to a closing title card. |
| `before-after` | The before picture, a wipe to the after picture, then both side by side under a headline. |
| `stat-countdown` | A countdown, a counter running up to the number that matters, and a kinetic closing line. |
| `title-into-tour` | A title card focus-pulls into a tour of three features, the camera gliding and whip-panning between screenshots. |

Agents use `find_templates` (a page at a time, with a `total`), `describe_template` (each slot's type, label, default and range) and `use_template` (`{ template, values, name? }`, which replaces the working scene and returns its issues and open slots). From the command line:

```bash
npx flair template list
npx flair template show product-reveal
npx flair template fill product-reveal --values values.json --set accent=#2266FF --set product=./mug.png -o launch.scene.json --html launch.html
```

## 🎬 Camera moves

A shot's `camera` frames a box (`{ x, y, width, height }`) or elements (`{ frame: ["card"] }`), can turn in 3D, and plays **camera moves from the catalog**: `in` is how the camera gets into the shot, and `during` is how it moves while the shot holds.

```json
{ "camera": { "frame": ["dashboard"], "tilt": 35, "turn": -15, "in": { "move": "camera-whip-pan", "values": { "motionBlur": 3 } }, "during": "camera-ken-burns" } }
```

Camera moves are catalog effects of their own kind (`kind: "camera"`, category `camera`), with controls and presets like any other. Their `motion.role` says where they go:

| Move | Role | What it does |
| --- | --- | --- |
| `camera-glide` | transition (the default `in`) | Eases across from the last framing, blurring with its speed when `motionBlur` is above 0. |
| `camera-whip-pan` | transition | Whips off the last framing in a streak of blur and whips in onto the next, cutting at the blurriest moment. |
| `camera-punch-zoom` | transition | Punches into the last framing to `punch` ×, blurring every way, and cuts to the next settling out. |
| `camera-cut` | transition | Jumps straight there, taking no time. |
| `camera-ken-burns` | hold | Drifts across the framing from one zoom to another. |
| `camera-crash-zoom` | hold | Crashes in on a `target` point in a few sudden steps, each landing with a kick. |
| `camera-handheld` | hold | Held by hand: drifts, sways and rolls round the framing (`amount`, `speed`, `roll`, `footsteps`, `seed`), never showing past its edges. |

- `in` and `during` take a move's id, or `{ "move", "ms"?, "preset"?, "values"? }`. `ms` sets how long a move into the shot takes (its own length by default; 600 ms for the moving ones). A hold's move plays across the shot's `hold`, and the next shot's move starts where it ends.
- `validateScene` names an unknown move, a move in the wrong field (a hold's move given as `in`), and a bad value, with the moves and controls there are. The scene tool `find_camera_moves` lists them for an agent.
- `tilt` leans the board back (top away, like a desk seen from above), `turn` swings it round its vertical axis (left side nearer when positive), `roll` rolls it clockwise. Tilt and turn go up to ±75°. Angles carry over to later shots until a shot changes them; `{ "camera": { "tilt": 0, "turn": 0 } }` flattens the board in place.
- `perspective` is the lens distance as a multiple of the stage width (1.2 by default). Lower values look more dramatic.
- On their own, `mountEffect` and `recordEffect` preview a move on a picture (`subject: { image }`), the picture standing in for a scene's board.

Camera moves move the **scene's camera** across its whole board. The catalog's transitions (a screen melt, a film burn…) and its picture zooms (`image-ken-burns`, `dramatic-zoom`) are different: they change pixels within one effect.

**Moving from the old fields:** `transition` and `motionBlur` were replaced by camera moves, and `validateScene` says what to write for each:

| Before | Now |
| --- | --- |
| `"transition": "move"` (or none) | `"in": "camera-glide"` (or none) |
| `"transition": "whip"` | `"in": "camera-whip-pan"` |
| `"transition": "zoom"` | `"in": "camera-punch-zoom"` (it punched to 1 + motionBlur ×; set `punch` to match) |
| `"transition": "cut"` | `"in": "camera-cut"` |
| `"motionBlur": 1.5` | `"in": { "move": "camera-glide", "values": { "motionBlur": 1.5 } }` |

`playScene` hands boards views with these fields (`View.tilt`, `View.blur`, `View.blurAngle`, …). For renderers:
- `cameraTransform(view, stage, width)` gives the CSS `transform` for a board layer.
- `cameraBlur(...)` gives the `stdDeviation` for an SVG `feGaussianBlur` that streaks, and `cameraFilter(...)` gives a CSS `blur()`.
- `projectPoint` gives where a scene point lands on screen.
- `cameraTrack` and `cameraSamples` lay the camera out on a timeline: each shot's `move` and `during`, sampled through the move and through a hold that has one.

The standalone player (`flair scene html`) plays all of it, with the scene's layers and transitions. Layout checks (framing, edges, text size, the title) are judged on screen, where the angle puts each element.

The exporters carry the camera too, keyed through every move (a hold's move included):
- **Lottie:** a "Camera" null layer that the element layers hang off. When the camera is angled, it is a 3D layer with an AE camera (lottie-web draws it with its `html` renderer).
- **Apple Motion:** a keyframed "Camera" group around the shots.
- **FCP7 XML:** a keyframed Distort corner pin on each shot's clip, plus Motion Blur.
- **EDL:** a `* CAMERA:` note naming the moves, since CMX 3600 has no transforms.

#### Sound and scrolling

Two more inputs, beside the pointer, that shaders read as built-ins (declared by the wrapper, so never in a source):

| Built-in | What it holds |
| --- | --- |
| `vec4 iAudio` | x level (loudness from RMS, 0–1), y bass (20–250 Hz), z mid (250–2000 Hz), w treble (2–16 kHz), each 0–1, smoothed (quick attack, slower release) |
| `vec4 iSpectrum[16]` | 64 log-spaced frequency bins (about 30 Hz to 16 kHz), 0–1, four to a `vec4`, low to high: bin `i` is `iSpectrum[i / 4][i % 4]` |
| `float iBeat` | seconds since the last beat (an onset on the bass band over its recent average), -1 before the first |
| `vec4 iScroll` | x the canvas's progress through the viewport (0 as its top comes in at the bottom, 1 as its bottom leaves at the top), y the page's scroll (0–1), z velocity (viewport heights per second, positive scrolling down, smoothed), w 1 while scrolling, easing back to 0 |

With no audio at all every audio uniform is 0, `iBeat` included; with a source connected `iBeat` is -1 or above 0. So an effect can tell silence from "nothing connected". Where nothing scrolls (thumbnails, recordings), `iScroll` is all zero. The catalog's audio and scroll effects play an idle demo then (a synthetic 120 bpm beat, or a page scrolled down and back), which their "Demo" control turns off.

```ts
import { ShaderRenderer, sharedAudioContext, analyseAudioBuffer, ShaderFrames } from "@pixerate/flair";

const preview = new ShaderRenderer(host);
preview.setSource(getEffect("spectrum-bars").source);
button.onclick = () => preview.setAudioSource(audioElement); // or a mic MediaStream, or any AudioNode; null stops
preview.setScrollProgress(0.5); // pin iScroll for a scrubber; null follows the page again

// Frame-exact, offline: the uniforms at any time of a decoded track.
const track = analyseAudioBuffer(await sharedAudioContext().decodeAudioData(bytes));
frames.render(t, { audio: track.at(t), scroll: [0.5, 0.5, 0, 0] });
```

- **Live sound.** `setAudioSource` makes an `AudioContext` (shared by every renderer: `sharedAudioContext()`) and an `AnalyserNode` on first use, and reads them each frame. A media element keeps playing to the speakers through Web Audio (an element can only be wired in once, so the node is reused). A microphone `MediaStream` is listened to, not played. Any `AudioNode` is analysed in its own context. Browsers start an audio context suspended until the page has a click or key press (the autoplay policy). Call `setAudioSource` from a click, or the context resumes on the first one. A media file from another site needs `crossOrigin = "anonymous"` and CORS, or the browser feeds silence. While a source is set, a paused preview still follows the sound. Dispose (or `null`) disconnects it.
- **The analysis.** `AudioAnalysis` is pure and unit-tested: it turns byte or decibel frequency data (`fftSize / 2` values) into the uniforms with log binning, band averages, attack/release smoothing and beat detection, and the same data at the same times always gives the same result. `analyseAudioBuffer(buffer)` runs it over a decoded track: a Blackman-windowed radix-2 FFT (`fft`, no dependencies) of the samples just before each time, as `AnalyserNode` would hear them, stepped 120 times a second from the start and kept, so frames asked in any order agree.
- **Scrolling.** `ShaderRenderer` follows the page with passive scroll listeners and `getBoundingClientRect` each frame (only when the shader reads `iScroll`), so a page or a scrolling element moving the canvas both count, and a paused preview still follows. `ScrollTracker` and `viewportProgress` are the pure parts.
- **Vector effects.** `new SvgPlayer(host, motion, { trigger: "scroll" })` scrubs the picture with its element's progress through the viewport instead of playing it on a clock: from the start at progress 0.1 to the end at 0.6 by default (`scrollRange`), back again as you scroll up. Hosts can drive any player with `player.setProgress(p)` (0–1), which stops a scroll trigger following the page.
- **Standalone pages.** `standaloneHtml(title, source, values, { audio: "song.mp3" })` adds a looping player in the corner that the page listens to once it plays, and `{ audio: "mic" }` a microphone button. The page itself does not scroll, so scroll effects play their idle demos there.
- **Thumbnails and the Node exporter.** `ThumbnailPool` and `flair render`/`flair export` declare the built-ins but feed no sound or scroll, so audio and scroll effects show their idle demos.

#### Broadcast graphics and annotations

The `broadcast` and `annotation` effects are animated SVGs in a 1920 × 1080 (16:9) frame, with their text inside the title-safe area. Each animates in, holds for its `hold` control (seconds) and animates out, ending as it started, so it loops; the news ticker is a seamless crawl instead. Lower thirds, the ticker, the score bug, the chapter marker, the subscribe button and every annotation draw on a transparent frame, to lay over video or a screenshot (`flair render lower-third --text "Ada Lovelace" --alpha -o lt.webm`); annotations are placed with position controls in percent of the frame. Every label is a text control, fitted to its length. Logos (`lower-third-stacked`, `logo-reveal`, `logo-sting`) take SVG path data in their `logo` control (`--path "M…"`), scaled to fit their slot and recoloured by the effect, so they draw on, shine and export as animated SVG like the rest; anything that is not path data draws a stand-in mark.

#### JSON Schemas

`effectControlSchema(id)` gives the JSON Schema (draft 2020-12) of an effect's control values, for forms, validators and agent tool layers. It is strict: an object of the effect's controls and nothing else (`additionalProperties: false`). Each control's label is its title, and its description gives its unit, range and default. `float` maps to a number and `int` to an integer, each between its `min` and `max`. `bool` maps to a boolean. A vector maps to an array of 2 to 4 numbers in range. A colour takes sRGB channels from 0 to 1, or a CSS colour string such as hex, `rgb()` or `hsl()`; in vector effects it also takes `"currentColor"`. An image takes a URL, or `""` for none. Every control has a default, so none is required. Units come from a `unit=` attribute on the `@control` comment, or from the label ("Size (px)" is in pixels). `controlsSchema(parseControls(source))` does the same for any shader.

`EFFECT_DOCUMENT_SCHEMA` (from `@pixerate/flair/editor`, and as a file at `@pixerate/flair/schemas/effect-document.json`) is the schema of an effect document. It checks shape only: which controls exist depends on the effect, so check values with `effectControlSchema` or `documentIssues`.

#### Loading the catalog on demand

The full catalog is about 425 KB gzipped, because it holds every effect's shader and picture. Where effects are listed, searched or offered to an agent, and only a few are drawn, import `@pixerate/flair/catalog/lazy` instead. It loads every effect's metadata up front (about 91 KB gzipped): ids, names, categories, descriptions, tags, controls, preset names, inputs and video use. `loadEffect(id)` then fetches the effect's shader or picture from a small module of related effects (a median of 12 KB, at most 26 KB).

```ts
import { findEffectMeta, loadEffect } from "@pixerate/flair/catalog/lazy";

const filters = findEffectMeta({ video: ["filter"] }); // same queries as findEffects
const crt = await loadEffect("crt"); // a ShaderEffect, with its source and presets
```

The full catalog has `loadEffect` and `effectMeta` too, so code can be written once for either catalog. The lazy catalog's effects are equal to the full catalog's, but they are not the same objects. After changing the catalog, `pnpm catalog:meta` regenerates the lazy catalog's metadata; a test fails until it is up to date.

Every shader is self-contained and compiles on WebGL2. Open [`#check`](https://pixerate.github.io/flair/#check) on the demo to compile the catalog on your own GPU. [`#bench`](https://pixerate.github.io/flair/#bench) times every shader per frame on your GPU (`#bench?size=720&only=aurora,fur` for a size or a few effects; keep the tab in front, since a hidden tab or other drawing inflates every number).

#### Rendering in Node

`flair render` and `flair export` render in headless Chrome, so a shader draws exactly as `ShaderRenderer` draws it: the same GLSL wrapper and built-ins (`iPointer`, `iClicks`, `iTrail`, and `iAudio`, `iSpectrum`, `iBeat`, `iScroll`, left at 0 so those effects play their idle demos), image controls (SVGs sized up first), `int` and `bool` controls. The output format comes from the extension:

| Output | Notes |
| --- | --- |
| `.mp4` | H.264, yuv420p, BT.709. Always opaque (`--alpha` is refused). |
| `.webm` | VP9; `--alpha` keeps transparency (yuva420p). |
| `.mov` | ProRes 4444; `--alpha` keeps transparency. |
| `.gif` | 256 colours a frame; `--alpha` gives one-bit transparency. No ffmpeg needed. |
| `.png` | Frames: a folder (`-o frames/`) or a pattern (`-o out_%04d.png`). No ffmpeg needed. |
| `.svg` | Vector effects only: one animated SVG (`svgAnimatedMarkup`), with no browser at all. |

Subjects: `--image` (a file or URL), `--svg` (a file, URL or markup), `--text` (with `--font`, `--weight`), `--path` (path data) and `--video` (a file, decoded with ffmpeg to one frame per output frame, looping a short clip; the render lasts as long as the clip, up to 10 s, unless `--duration` says). Repeat a flag for effects that take two pictures, such as transitions. `--set name=value` sets a control (numbers, `true`/`false`, colours like `#ff0080`, or comma-separated vectors), over `--preset`.

Without `--alpha`, overlays are drawn over `--background` (black for shaders, white for vector effects).

`--shutter-angle <degrees>` (`shutterAngle`, 0 to 360, default 0) adds motion blur to video, GIF and PNG output, on `flair render` and `flair export` alike: each frame is the average, in premultiplied alpha, of `--shutter-samples` renders (`shutterSamples`, 2 to 32, default 8) spread across the time the shutter is open, `(angle / 360) / fps` seconds from the frame's time. 180 is a film camera's usual. The scripted pointer and a vector effect's timeline are acted out at every sub-frame; a `--video` subject shows the same frame across them. The render draws `shutterSamples` pictures per frame, so it takes about that much longer. `.svg` output has no frames to blur, so a shutter is refused there.

To see an overlay that takes no picture of its own (sparkles, bokeh, confetti) over a photo, give it a backdrop: `--backdrop photo.jpg` (a file or URL; `backdrop` in code, which also takes a `data:` URL, and `{ imageBuffer, ext }` in `exportEffectBuffer`) is drawn under the effect in every frame, and the frame takes the photo's size unless `--size` says (JPEG rotation included). `--backdrop-fit` is `cover` (the default: fill and crop), `contain` (fit whole, over `--background`) or `fill` (stretch). `--region x,y,w,h` (`region: [x, y, width, height]`, normalized 0 to 1 from the top left) confines the effect to part of the frame; it renders at that box's size, so it is not stretched. A backdrop is refused with `--alpha` (it fills the frame), with `.svg` output, and for a shader that draws every pixel itself (give an image effect the photo as `--image` instead).

```bash
flair render sparkles --backdrop beach.jpg -o beach.mp4
flair render sparkles --backdrop beach.jpg --region 0,0,1,0.5 --size 1280x720 -o sky.png
``` Effects that answer the pointer get a scripted one that hovers, wanders and clicks (`--no-pointer` leaves it still); click-triggered vector effects are clicked through their steps, and hover or press ones play through and back.

Chrome is found in the usual places, in Playwright's downloads, or at `CHROME_PATH`; ffmpeg on the `PATH` or at `FFMPEG_PATH`. The same from code:

```ts
import { exportEffect, exportMotionGraphic } from "@pixerate/flair/node";

await exportEffect("image-duotone", { subject: { image: "team.jpg" }, preset: "Spotify", outputPath: "team.mp4" });
await exportEffect("click-ripple", { alpha: true, outputPath: "ripple.webm" });
await exportEffect("toggle-switch", { outputPath: "toggle.svg" });
await exportEffect("sparkles", { backdrop: "beach.jpg", backdropFit: "cover", region: [0, 0, 1, 0.5], outputPath: "beach.mp4" });
await exportEffect("neon-warp", { shutterAngle: 180, shutterSamples: 8, outputPath: "warp.mp4" });
await exportMotionGraphic({ source, values: { speed: 2 }, outputPath: "out.gif", duration: 2 });
```

Limits: vector frames are drawn with `svgFrameMarkup`, so a change `along` a path and a `view` that frames an element by id stay where the markup puts them; GIF frame delays are whole hundredths of a second (30 fps plays at 33.3).

#### Swift & Metal (`FlairEffects`)

Every catalog shader effect compiles to Metal Shading Language (MSL 2.1) and ships as a native Swift package in [`swift/`](./swift) (`FlairEffects`, targeting iOS 17+ and macOS 14+):

- **441 shader effects**, typed as `FlairEffect & Sendable & Equatable & Codable` structs (`MeshGradient`, `Aurora`, `Crt`, `LiquidGlass`, …) with `@control` properties, presets, `std140` uniform packing, and web-compatible `Codable` JSON (`uSpeed`, hex or `[r, g, b]` colours).
- **Textures, text & SVG paths**: `sampler2D` inputs bind at `[[texture(0..7)]]` alongside a bilinear clamp sampler at `[[sampler(0)]]`, with native `FlairTextRasterizer` (CoreText) and `FlairPathRasterizer` (packs SVG path data or pixel points into the same `256 × 2` point texture as the web `pathTexture`, so the shader's `PATH` helpers fit it to the frame).
- **Multi-pass & feedback**: `FlairPipeline` executes multi-pass chains (`passes`, `inputs`) and ping-pongs double-buffered `feedback` targets across frames.
- **Interactive built-ins**: `iPointer`, `iClicks`, `iTrail` (`FlairPointerTracker`), `iAudio`, `iSpectrum`, `iBeat` (`FlairAudioTracker`), and `iScroll` (`FlairScrollTracker`).
- **SwiftUI & MetalKit**: `FlairEffectView`, `.flairBackground(...)`, `.flairOverlay(...)`, and offscreen `FlairRenderer` (`renderImage(effect:size:)`).

The repository root has a `Package.swift` too, so a Swift app can depend on this repository directly. Each release commit carries a plain semver tag (`0.110.0`, from 0.110.0 on) next to npm's `@pixerate/flair@x.y.z`, so SwiftPM resolves Flair by version:

```swift
.package(url: "https://github.com/Pixerate/flair.git", from: "0.110.0"),
// …
.product(name: "FlairEffects", package: "flair"),
```

```swift
import SwiftUI
import FlairEffects

struct HeroCard: View {
    var body: some View {
        Text("Flair on Metal")
            .font(.largeTitle.bold())
            .padding(32)
            .flairBackground(MeshGradient(preset: "Sunset"))
    }
}
```

##### Flair in the Pixerate editors' Swift package (`FlairEditorEffects`)

`FlairEditorEffects` is the Swift side of `flairEffects()`: `FlairEffectProvider` implements the `EffectProvider` of the [Pixerate editors' Swift package](https://github.com/Pixerate/editor) (`PixeratePaint`), so a Swift editor gets Flair's Metal shaders as effect paper, effect layers, fills and effect paint, saved and replayed like any provider's. The editor never depends on Flair; the product is optional, so an app that only takes `FlairEffects` never fetches the editor.

```swift
.product(name: "FlairEditorEffects", package: "flair"),
```

```swift
import FlairEditorEffects
import PixeratePaint

let controller = try PaintEditorController(width: 1024, height: 768)
controller.setEffectsProvider(FlairEffectProvider())
_ = try await controller.addEffectLayer("aurora", values: ["uSpeed": 0.5])
_ = try await controller.fillLayerWithEffect("image-duotone") // a filter: the layer is its source
```

It offers every shader in `FlairEffects`, described exactly as `flairEffects()` describes them (ids, uses, controls as JSON Schema, defaults, presets, inputs and durations, written by `pnpm swift:meta` into `swift/Sources/FlairEditorEffects/Resources/flair-effects.json`), so a document saved by a web editor opens in a Swift one and the other way round. Renderers draw on the GPU and return straight-alpha RGBA8: a filter's `source` and a transition's `from` / `to` are the shader's pictures, a transition follows `progress` (else `time` over its duration), colours take any CSS form the schema allows, and a mask keeps the untouched picture where it is 0. Refusals are `EffectError`s that say what to do (`unknown_effect`, `invalid_values`, `unsupported`, `disposed`). Paint hints come the same way (`paint` on summaries and descriptions, with `capabilities["paintHints"]`), so a new Flair effect with a hint becomes a paint after a version bump. Not yet offered: vector and motion effects (`VectorEffectProvider`), camera moves, timing effects and float pixels.

`FlairEffectProvider` is also an `AuthoringEffectProvider`, so the editor's Effect Authoring tab and its `effect_authoring_*` tools (and a paint editor's `open_effect_authoring`) edit Flair effects: `openAuthoring(.effect("aurora", preset: "Ember"))` opens a catalog effect in the editor's `GenericEffectAuthoringSession` for its values, presets, keyframes and timing, with undo and a preview, and `openAuthoring(.document(json))` opens a document saved by `exportDocument` on either side. The Swift adapter draws Flair's shaders compiled to Metal ahead of time and has no GLSL compiler on the device, so a catalog effect's session has no source to edit. A document keeps the catalog shader when its GLSL matches the `sourceHash` `pnpm swift:meta` writes. A document whose GLSL was edited on the web opens and draws when it carries Metal compiled from that GLSL in `provider.metal`: add it where the Metal tools are with `npx flair export metal-document doc.json out.json` (or `attachFlairMetal(doc)` from `@pixerate/flair/node`). Its session shows the GLSL (`sourceLanguage: "glsl"`) and saves it with the Metal; an edit to the GLSL on the device can't compile (the issue says so) and drops the Metal, and undo brings both back. Without Metal, or with Metal made from other GLSL, it is refused saying how to compile it. A shader, catalog or run-time (`FlairRuntimeEffect`, `FlairRenderer.loadLibrary`), gets 2 seconds to compile (`compileTimeoutMs`, as the editor's pixel expression shaders) before the renderer refuses. Paint editors keep a saved Flair document as an authored effect, and draw it through the provider, only with `PaintEditorController(rawShaders: true)` (default `false`); effects written at run time use the editor's own pixel expressions instead.

Use `npx flair effects --swift` (or `findEffects({ swiftReady: true })` / `findEffectMeta({ swiftReady: true })`) to filter catalog effects available in `FlairEffects`. After adding or editing a shader in the catalog, regenerate the Metal shaders and Swift sources with `npx flair export metal` (requires `glslangValidator` and `spirv-cross`, e.g. `brew install glslang spirv-cross`; add `--verify` on macOS to compile-check every `.metal` file with `xcrun -sdk macosx metal`). From Node, `compileShaderToMetal` and `exportMetalPackage` from `@pixerate/flair/node` run the same pipeline programmatically, and `attachFlairMetal(document)` adds a saved authoring document's Metal (`provider.metal`: the MSL, its uniform layout, the description for its controls and a SHA-256 of the GLSL it was made from).

#### Agent skills

Flair ships two [agent skills](https://docs.claude.com/en/docs/claude-code/skills) in the package's `skills/` folder, for coding agents (Claude Code, Cursor and others) writing code that uses Flair:

- **`flair-use`**: finding an effect (a generated index of every effect, one line each, by group), choosing an entry point (React, Svelte, embed, the lazy catalog, Node), controls, presets, camera moves, scenes, and checking the result.
- **`flair-author`**: writing custom shader and vector effects, with `flair controls` as the check.

**Claude Code plugin.** This repository is a Claude Code plugin marketplace (`pixerate`) with one plugin, `flair`, holding both skills:

```text
/plugin marketplace add Pixerate/flair
/plugin install flair@pixerate
```

Claude uses them by itself when a task involves Flair, or call them as `/flair:flair-use` and `/flair:flair-author`. Add `--scope project` to both (`claude plugin marketplace add Pixerate/flair --scope project`, `claude plugin install flair@pixerate --scope project`) and commit `.claude/settings.json` to give a whole repository the plugin. The plugin's version follows the package's, so it updates with each release. The skills run the project's own CLI, so install `@pixerate/flair` in the project too.

**Copying them into a project** (any agent): `npx flair skills install` copies them into `.claude/skills` (`--dir` for another folder, such as one your agent reads; `--skill flair-use` for one of them). Run it again after upgrading Flair: it brings changed files up to date and leaves files of your own alone. From code, `installSkills({ dir, skills })` from `@pixerate/flair/node` does the same.

See [Agent Skills & Claude Code Plugin](https://flair.pixerate.com/editor-and-agents/agent-skills/) on the docs site. The skills are plain Markdown and name only what exists: a test checks every entry point, export, CLI command and flag, effect id, preset, template, motion primitive and agent tool they mention, and `pnpm catalog:meta` regenerates the effect index.

## 🧪 Testing code that uses Flair

There are two ways to test, depending on whether you need real pixels:

- **No GPU** (jsdom, Node, CI): `installFakeWebGl()` from `@pixerate/flair/testing` makes canvases, and `OffscreenCanvas`, hand out a fake WebGL2 context. `ShaderFrames`, `ShaderPipeline`, `ShaderRenderer` and `flairEffects()` then construct, compile and render as they would on a page.
  - No shader runs. Pixels come from `pixel(x, y, time)`, so the same calls always give the same frame.
  - Each fake records the calls made on it, including the uniforms set and the textures bound to each draw.
  - A source containing `COMPILE_ERROR` fails to compile with `compileLog`, to test error paths.
- **Real pixels that match across machines** (golden images): render with `software: true` (`exportEffect`, `exportMotionGraphic`), `--software` on `flair render` / `flair export`, or `FLAIR_SOFTWARE_GL=1`. Headless Chrome then draws with SwiftShader, its software GL, on every platform rather than the machine's GPU, so frames match wherever the same Chrome runs.

```ts
import { installFakeWebGl } from "@pixerate/flair/testing";
import { flairEffects } from "@pixerate/flair/integrations";

const webgl = installFakeWebGl({ pixel: (x, y, t) => [x, y, Math.round(t * 60), 255] });
const renderer = await flairEffects().createRenderer("crt", { width: 4, height: 4 });
const frame = await renderer.render({ time: 500, inputs: { source: { width: 4, height: 4, data: new Uint8ClampedArray(64) } } });
expect(webgl.last().uniform("iTime")).toEqual([0.5]);
webgl.restore();
```
