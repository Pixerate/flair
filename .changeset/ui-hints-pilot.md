UI hints on effect descriptions (pilot). Effects that work as UI components now say so: `effectMeta(effect).ui` / `getEffectMeta(id).ui` and `flairEffects()` summaries and descriptions carry `ui`, a `UiDescriptor` as `@pixerate/schemas` defines it (`implements`, `group`, `contract` with props as JSON Schema, controlled state, events, a11y, colour roles and sizing, `platforms`, `example` and a `contentHash` that changes when the effect's output does), and `uiBindings`, which says which controls its props, colour roles (`{ "track-on": "on", … }`) and state drive; the provider declares `capabilities.uiHints`. The first three are `toggle-switch` (`switch`), `progress-bar` (`progress`) and `gauge` (`gauge`, `data-visual`), in `UI_HINTS` (`@pixerate/flair/catalog` and `/catalog/lazy`). `mountEffect`, React's `<FlairEffect>` and Svelte's `flairEffect` take typed `data` (refused with a sentence when it does not fit; `uiValues` gives the control values), a controlled `state` with `onEvent` (a controlled switch fires `change` and moves only when the host passes the new state; `setState` / `setData` on the mounted effect), a `label` and `reducedMotion`; components set their ARIA role, state and keys, play once to their rest point and show it still under reduced motion. `SvgPlayer` gains `onTrigger` (intercept a click trigger) and `settle()` (jump to the rest of the current step).
